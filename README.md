# ClinicCare Mini EMR

A minimal Electronic Medical Record app: doctors log in, search ICD-10 diagnosis codes, record patient consultation notes, and list/search past consultations.

## Stack

- **Backend:** FastAPI + SQLAlchemy + PostgreSQL + Alembic
- **Frontend:** Nuxt 3 (Vue 3)
- **Auth:** JWT access token + refresh token (rotation)
- **Database:** PostgreSQL, run via Docker Compose

## Architecture & request flow

Two independent services — the browser never talks to the database directly, and the frontend never talks to it either; everything goes through the API.

```
Browser
  │  (Nuxt page/component)
  ▼
composables/useApi.ts  ──attaches Authorization: Bearer <access_token>──┐
  │  (get/post)                                                        │
  ▼                                                                     │
HTTP request (CORS-enabled)                                            │
  │                                                                     │
  ▼                                                                     │
FastAPI routers/  →  services/  →  models/ (SQLAlchemy ORM)             │
                                        │                                │
                                        ▼                                │
                                   PostgreSQL                            │
                                                                         │
On 401 (expired access token): useApi calls /auth/refresh once ────────┘
(deduped across concurrent requests), stores the new tokens, retries.
```

**Auth flow:**
1. `POST /auth/login` (email + password) → returns a short-lived **access token** (15 min, JWT) and a long-lived **refresh token** (7 days, opaque random string).
2. Every API call attaches `Authorization: Bearer <access_token>`.
3. When an access token expires, the frontend automatically calls `POST /auth/refresh` with the refresh token, gets a **new pair** of tokens (the old refresh token is immediately revoked — single-use rotation), and retries the original request. The user never sees this happen.
4. `POST /auth/logout` revokes the refresh token server-side.

## Project structure

```
backend/
├── app/
│   ├── config/       # env-driven settings (CORS, JWT) as self-contained modules
│   ├── database.py   # SQLAlchemy engine/session
│   ├── exceptions/   # AppError hierarchy + centralized FastAPI exception handlers
│   ├── models/        # SQLAlchemy ORM models (one file per table)
│   ├── schemas/       # Pydantic request/response schemas
│   ├── security/      # password hashing, JWT issue/verify, current-user dependency
│   ├── services/       # business logic (one class per domain, DB session injected)
│   ├── routers/        # FastAPI endpoints — thin, delegate to services/
│   └── main.py
├── alembic/            # DB migrations (source of truth for schema)
├── db/db.sql           # reference schema + seed practitioner (for manual/local use)
├── seed/                # ICD-10 seed data generated by scrape_icd10.py
└── requirements.txt

frontend/
├── components/         # DiagnosisPicker, ConsultationTable (shared across pages)
├── composables/        # useApi (HTTP + auto-refresh), useAuth (login/logout/tokens)
├── layouts/             # default (app shell + nav), blank (login page)
├── middleware/          # auth.global.ts — redirects to /login if not authenticated
├── pages/               # login, consultations (list/new/search)
└── types/               # shared TypeScript interfaces, mirrors backend schemas/

scrape_icd10.py          # scrapes real ICD-10-CM codes from icd10data.com into backend/seed/
docker-compose.yml        # Postgres for local dev
```

## Setup

### 1. Database (Docker)

```bash
docker compose up -d
```

### 2. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # then set a real JWT_SECRET_KEY and POSTGRES_PASSWORD
alembic upgrade head
psql "$DATABASE_URL" -f db/db.sql            # sample practitioner (see credentials below)
psql "$DATABASE_URL" -f seed/icd10_seed.sql  # 100 real ICD-10 codes
uvicorn app.main:app --reload
```

API docs: `http://localhost:8000/docs`

### 3. Frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

App: `http://localhost:3000`

## Environment variables

**`backend/.env`**

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string (built from `POSTGRES_USER`/`PASSWORD`/`DB`) |
| `CORS_ORIGINS` | Comma-separated list of origins allowed to call the API from a browser |
| `JWT_SECRET_KEY` | Signing key for access tokens — must be set, no default |
| `JWT_ACCESS_EXPIRE_MINUTES` | Access token lifetime (default 15) |
| `JWT_REFRESH_EXPIRE_DAYS` | Refresh token lifetime (default 7) |

**`frontend/.env`**

| Variable | Purpose |
|---|---|
| `NUXT_PUBLIC_API_BASE` | Backend base URL (default `http://localhost:8000`) |

## API endpoints

| Method | Path | Auth required | Description |
|---|---|---|---|
| POST | `/auth/login` | No | Exchange email/password for an access + refresh token |
| POST | `/auth/refresh` | No (refresh token in body) | Exchange a refresh token for a new token pair (rotates it) |
| POST | `/auth/logout` | No (refresh token in body) | Revoke a refresh token server-side |
| GET | `/auth/me` | Yes | Current authenticated practitioner |
| GET | `/diagnosis?search=&limit=` | No | Search ICD-10 codes (code-prefix or description match) |
| POST | `/consultation` | Yes | Create a consultation note; `created_by` comes from the token |
| GET | `/consultation?patient=&diagnosis_code=` | No | List/search past consultations |

## Database schema

Managed entirely through **Alembic migrations** (`backend/alembic/versions/`) — `backend/db/db.sql` is a plain-SQL reference/seed file, not the schema's source of truth.

- `practitioners` — doctors (email, hashed password, role)
- `patients` — name, date of birth, gender
- `diagnoses` — ICD-10 code + description
- `consultations` — patient, note, diagnoses (many-to-many), who created/updated it
- `refresh_tokens` — SHA-256 hash of each issued refresh token (never the raw token), with expiry + revoked flag
- `audit_logs` — generic create/update/delete trail (table, record, who, when, before/after snapshot)

## Frontend pages

- `/login` — sign in
- `/consultations` — table of past consultations
- `/consultations/new` — record a new consultation (patient info, diagnosis picker, note)
- `/consultations/search` — filter consultations by patient name or diagnosis code
